# 返表回填与问题记录

适用于收到用户编辑过的校对表、核查“哪些还没校对”，或整理手误 Word。表格版式继续遵循用户附件及[校对稿格式](review-workbooks.md)，这里不规定固定列字母、游戏字数或发布版本。

## 保留证据并确定采用稿

- 保留返回文件原件、原始导出快照、稳定 ID／分段映射及对应游戏构建指纹。实际回填从最新已确认的构建、译文与字码别名继承，不能用早期生成器默认路径覆盖后来修复。
- 同时检查“修订中文”和允许编辑的“现用中文”列。常见约定是非空修订优先；修订为空而现用中文相对导出快照确有变化时，也应纳入。但以本表约定为准；两列互相矛盾时保留冲突证据，不能只因一列更靠右就认定用户最终意图。
- 将空单元格的 None 与空字符串作为比较层面的同值，避免导出软件重存产生数百条假修改。不要据此清空游戏文本；有意删除用明确标记或用户说明识别。也不要全局去空格、折叠换行或 NFKC 规范化后直接回填，这些可能影响排版和控制码。
- 验证 ID、原文指纹与身份字段；行号只帮助人工查找。对长文的续行，按导出时的分段契约重组，比较完整条目，防止在第一格填写全文后又拼回旧续段、增加分隔符或漏掉末段。无法确定分段意图时先记录冲突，继续其他明确条目。
- 一句逻辑文本对应多个物理槽时，依原有映射逐一写回与读回；不按字符串相同就盲目全局替换。分别统计编辑单元格、逻辑条目和物理位置，避免混用“修改条数”。

## 区分已交回和未校对

返表出现过、明确审校通过、实际改过、当前镜像已采用，是四种不同证据。空修订通常表示沿用原译，不能单凭空格认定没看过，也不能反过来把所有空格都标成明确验收通过。按原工作流的返表含义记录状态；不以实际 changed 列表代替整份返表覆盖范围。

重新整理待校表时，先合并历史返表中的稳定身份覆盖；已交回而当前译文有差异的单独列出。找不到历史证据只说明“未找到记录”。邮件数量等完整性结论应结合程序槽数、目录／加载关系、空槽和实体内容验证；一次关键词搜索或当前导出的行数不能证明全量。

## 手误与指定译名

用户允许修明显错字时，只修有上下文支持的同音错字、重复字、误标点或明确漏字；简称拼写需要与原文及同一机构核对。独特译名、文风、术语偏好不能因不常见就改掉。

维护一份可追踪清单：稳定 ID、原表位置、返稿原句、疑似问题、建议改法、实际采用稿和处理状态。原句照录错字，建议与已采用分开。多处相同错误可合并，但保留每个位置。明显串句或缺失成分可对照原文提出补全建议；若已超出明确错字授权，先作为待核对项，不用个人润色替代用户译稿。

用户要简单 Word 时，正文说明“原文”指返稿摘录还是游戏原语言，用轻量表格或短段列出原句与问题即可。指定译名保留、待核对项另列。记录文件不是已回填或已发布的证明；后续若采用，更新处理状态并关联构建验证。

## 中文 Word 的预览缺字

适用场景：生成的 DOCX 文本存在，但 bundled LibreOffice 预览里中文空白或方框。先按可用的 documents 技能完成渲染检查，不以文件能保存或 XML 有字作为视觉验收。不要把文档字体故障归因于游戏字库。

本机一次已验证的解决方式是给渲染进程指定独立 Fontconfig 配置，显式加入可读的中文 OTF／TTF 目录，并将 DOCX 的西文／东亚字体设为对应字体族。只设置 SAL_FONTPATH 在该次环境无效；这不说明所有 LibreOffice 构建都如此。

配置模板如下，替换成当前已确认存在的绝对目录；缓存放可写工作目录。无需修改系统字体配置或插件缓存。

```xml
<?xml version="1.0"?>
<!DOCTYPE fontconfig SYSTEM "urn:fontconfig:fonts.dtd">
<fontconfig>
  <dir>/absolute/path/to/cjk-fonts</dir>
  <dir>/absolute/path/to/runtime-fonts</dir>
  <cachedir>/absolute/path/to/writable/font-cache</cachedir>
</fontconfig>
```

通过当前技能／依赖加载工具取得实际 bundled Python 与 render_docx.py 路径，再运行：

```sh
FONTCONFIG_FILE="/absolute/path/to/fonts.conf" "/absolute/path/to/bundled/python3" "/absolute/path/to/render_docx.py" "review.docx" --output_dir "preview"
```

修改字体或布局后重新渲染所有页，逐页检查中文、表格跨页、裁切及标题。Word 模板的标题边框或主题字体可能在直接改字体后仍保留，按实际样式清除，而非用白色图形遮盖。上述配置解决的是作者侧预览；不代表接收者安装了同一字体，交付仍按需求选常见字体或在许可允许且必要时嵌入字体。用户只要 Word 时只交付 DOCX，QA 图片／PDF 留工作目录。
