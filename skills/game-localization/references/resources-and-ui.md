# 资源写回、字库与界面

涵盖二进制封包与指针、字码/字形/排版分离、固定字数换行、UI 贴图重绘与内存预算。

## 1. 封包与指针

- 记录端序、编码、长度单位、地址基准、对齐、压缩、校验、成员顺序与加载方式。原样往返先验证未修改成员逐字节一致；压缩表示不同时解释差异并比较解压成员。补充独立读回、边界断言与已知样本，不只靠同一读写器互证。
- 长度可能是字符、字节、含终止符长度或对齐块数；指针可能相对文件头、表基址或运行地址。传统 ROM 另需注意 bank/映射、DTE/MTE 压缩与嵌入指针。译文增长必须重算位置并更新全部引用，不可简单整体后移。
- 顺序字符串池多一个 NUL 会导致后续全错位；保留空条目、控制码与结束标记。回填核对指针范围、条目数、成员长度、父容器长度与未修改区域。内部资源键、文件名、路径分隔符与大小写不得随文字改动。
- 脚本中的空格、换行与注释邻接可能是词法分隔符，按实际 tokenizer 验证条目分组与数量。控制码按引擎语法匹配：限定 ASCII 数字时用 `[0-9]` 而非 Unicode `\d`，防止吞入紧邻的全角数字或中文。

## 2. 字码、字形、排版分离

- 维护 `语义 Unicode → 游戏字码 → 字形索引 → 图集页/UV → 字宽/轴承/基线`。旧汉化可能借用日文字位导致多义冲突，换字体前必须发现并拆分。
- 同一行字形共用统一基线，不按单字包围盒顶部独立贴齐；用“一”、常用标点与中英混排核对垂直位置，并修复生成器本身而非仅修预览图。
- 所需字符覆盖静态文本、动态变量、命名界面、数字、标点、拉丁字母与回退字形。同一游戏的不同消费者（普通正文、双倍字、按钮、战斗、广播）可能走不同渲染器（如单字节 vs 双字节）；正文正常不代表按钮兼容中文。
- 已烘焙到游戏纹理的字体与构建机字体分开：缺字先查字码映射、资源版本与加载层，不误报“缺少系统字体”。整套换字体时导出带语义标签的字形接触表逐字核对，不以少量截图代替。

## 3. 固定字数换行

- 按实际文本框、字号与渲染入口配置上限，不给全游戏强套单一字数。像素度量可用时优先测量；用字位上限时明确中文、标点、空格、ASCII 计数方式，并为动态变量最大展开预留空间。
- 区分软折行、语义段落与分页/图示/等待事件，仅合并确认属于软折行的内容，再执行避头尾禁则（闭标点不独占行首，开括号不落行尾）。
- 横向合规后复查每页行数与提示框高度，避免纵向溢出；超限项必须报错，禁止静默截断。

## 4. UI 贴图重绘

- 按原 UI 建立正文/标题/字幕字体层级并原尺寸预览；统一字体指统一层级与度量，而非所有位置同字号。
- 记录每个文字区的 sprite UV、缩放、对齐锚点、基线、留白、裁切与选中/禁用状态。同组按钮采用统一字号、基线与锚点，不把短词拉伸到长词宽度，也不按英文原图字框分别缩放。
- 保留原纹理像素排列、调色板、alpha 约定、mipmap、swizzle、透明边缘与压缩格式；压缩纹理以实际重编码块为修改边界，独立解码核对非目标块与边框像素。
- **贴图重绘规范（禁止盖块叠字）**：
  - 严禁在原文字上盖纯色矩形、黑块或透明洞后直接叠中文字。
  - 建立可复现的底图/装饰层与中文文字层：拆出并保留边框、斜角、渐变、网格、纹理、描边、高光与图标，从匹配原版或干净样本重建文字下方背景后再排字；纯文字透明 sprite 直接生成新透明文字层。
  - 按实际 sprite UV、可见区与显示锚点排版，不因 OCR 误判删掉装饰箭头或边线。
  - 发现一处覆盖式缺陷时，审计当前项目全部同类已改贴图及共用生成器，同步修正所有物理副本。
- 大标题模糊先排查采样分辨率、分片/UV、引擎缩放、基线、alpha 与滤波；重排字不等于提高原始贴图分辨率。重复资源按内容、结构与引用确认身份，每个物理副本写入后独立解码预览。

## 5. 内存预算

统一字体、共用码表、按需子集与紧凑像素格式步骤见 [字库压缩与复用](font-memory.md)。

- 宿主主机 RAM 不等于被模拟主机的地址空间或游戏堆限制；分别记录磁盘大小、解压大小、纹理分配、对齐/头开销、同时驻留量、加载释放时机与最大连续块。
- 优先无损去重、图集重排与经引用分析证实不可达的页；仅压缩磁盘文件未必减少运行时 RAM。
- 扩大图集或转格式前先预算峰值；区分“字库过大触发分配失败”与“分配失败未检查返回值”，缩小字库不等于补上了错误处理。保存精确构建、申请长度、载入资源与触发步骤，复测原场景及其他高驻留场景。
