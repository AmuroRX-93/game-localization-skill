# 字库压缩与复用

用于统一字体、扩中文字库以及排查扩字引发的加载黑屏或内存不足。目标是在保留语义、字形与排版的前提下，减少重复数据与峰值驻留，而不是盲目降画质或删字符。

## 1. 四层复用（逐层证明兼容性）

1. **字体源统一**：优先使用同一字体家族、版本与必要字重，固定地区变体源文件指纹并保留许可；统一风格不要求全界面同字号。
2. **语义码表统一**：维护 `Unicode → 游戏字码 → 字形索引` 的稳定映射；新增字符复用安全码位，禁止不同资源把同一码位赋成不同汉字。单/双字节渲染器必须分表时，保留统一语义表与明确转换。
3. **字形与文件复用**：字体源、字符、字号、度量、描边、像素格式和布局完全一致时直接复用已验字形；资源按内容、结构与引用去重，构建时生成一份规范资源再向物理引用分发并逐份校验。
4. **运行时实例复用**：优先沿用加载器已有共享槽/缓存；新增共享须确认引用计数、所有权、加载释放时机与格式兼容，防止某场景卸载另一场景仍在用的图集。

一套规范字库可派生少量按需规格；不要为了只剩一个文件，把全字符、全字号塞进一张常驻大图集。

## 2. 先盘点消费者，再按优先级压缩

为每个字体槽建立需求表：加载入口、消费者、实际字符串、必需字符、动态来源（变量展开、玩家命名、数字、标点、按钮符号、回退）、原字符、像素格式、单字尺寸与驻留区间。未查清动态入口时保留原覆盖；清除假名、空白字形或正文未出现字符不是可靠压缩方法。

压缩优先级：
1. 复用已有合格字形与完全相同的资源。
2. 移除经消费者分析证实多余的**额外扩字**（尤其是固定短标题、数字字库），保留原字符覆盖与该消费者所需中文。
3. 格式允许时合并完全相同的字形图像/图集页，保留各语义码位与 metrics，并更新全部 UV/偏移/页索引。
4. 改用该版本加载器原生支持的紧凑像素格式（如白字改 LA8/A8/索引色）；核对通道顺序、alpha 精度与预乘方式，彩色字形不可盲转。
5. 裁剪透明填充只在尺寸、步长、UV、bearing 与绘制几何全部可正确修正时执行；降低字号或分辨率属于质量取舍，单独评估，不冒充无损压缩。

## 3. 内存预算与离线/运行验收

- 分开记录磁盘文件、解压后 CPU 数据、GPU 内部纹理、上传暂存、头表与对齐、同时驻留量及最大连续块。像素粗估公式：`Σ(字形数 × 单字宽 × 单字高 × 每像素字节数)`。
- 磁盘压缩通常只省存储，不省加载后 RAM；输入格式从 RGBA8 改 LA8 若渲染器内部仍转 RGBA，也不能声称显存减半。
- 排查扩字黑屏时，将“减少额外扩字”和“转换像素格式”做成独立候选分别验证，不同时改动译文、模拟器设置或启动程序。
- 独立读回比较所有保留字形的像素、语义码位、字宽、基线与索引引用；封包后逐成员回读，确保未修改分支保持原样。

## 4. 参考实例（按需子集 + 原生紧凑格式）

某 PS3 作品（9 份字体文件）在沿用同一字体源与共享码表的前提下，经消费者定位发现两份固定标题字库被多灌入 290 个额外字形；仅移除多余扩字后，总文件量由约 40.05 MiB 降至 22.36 MiB，再利用该版本原生支持的 LA8 输入分支进一步降至 11.19 MiB，全部 3,499 个保留字形独立回读一致，原战斗入口黑屏消失。需注意：LA8 对应内部纹理仍为 RGBA，不能把文件体积缩减比例等同于显存缩减比例，也不代表其他游戏均支持 LA8。
