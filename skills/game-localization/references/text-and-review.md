# 文本、语言与校对

涵盖资源分母盘点、提取真实性、日/英译中专项要点、术语规则、校对表设计与返表回填。

## 1. 建立分母与覆盖率口径

- 资源总表记录：外层文件与指纹、容器链、成员标识/偏移、类别、解析状态、加载证据、关联条目与处理决定。覆盖文本表、脚本/可执行文件字符串、按键帮助、功能贴图、片头标题、字幕以及更新、DLC、安装副本与单人/多人变体；每类标记为“找到 / 经证据排除 / 待查”，未知容器不从分母消失。
- **分开统计分母**：物理出现次数、唯一文本 ID、唯一字符串、段落与表格行数不是同一口径；列出各工作表条数及汇总方式。
- 可见条目分别标记 `translate / retain / exclude / pending`，后两种需附理由。改变不等于翻译，未改变也可能是正确保留的型号。覆盖率仅对明确版本与已盘点集合有效。

## 2. 提取真实性与实际使用

- 正则/编码扫描只产生候选；按版本与记录结构核实字段起点、长度、终止符，防止浮点数、指针、模型数据或旧偏移被误当正文。导出后批量重读源字节核对指纹与 ID（这证明提取可追溯，不证明游戏实际显示）。
- 将提取异常、真实文字的旧副本、疑似调试/备用资源与用途待查分开分类。未查到文件名引用不代表全局不可达（可能通过数值 ID 或动态路径加载）。
- 交付清单分别列出：结构化原生文字、程序/辅助字符串、图片 OCR、语音/影片与未解析资源。OCR 保留原图、成员定位与待校正栏；仅盘点音频未转写不能称完整剧情提取。

## 3. 日译中与英译中要点

先确定主译版本、源语言、目标中文地区与参考译本；不通过第三种语言中转已有原文。日英双版本可能来自不同发行或修订，以主译版本的 ID、场景和分支为准，另一版仅作注明出处的参考；无法可靠对应的行留空标缺失，不用机器回译伪造原文。

### 日译中
- 根据上下文、说话人、事件和分支补足省略的主语/宾语；证据不足先标待核对，不擅自补剧情。
- 区分人名、公司、队伍、武器名与普通片假名借词；按批准术语表处理长音、简称与复合词。
- 保持敬语、口癖、称呼与人物关系一致；片假名外来词核对设定，不凭音译反推唯一英文原名。
- 核对同形汉字、否定、条件与操作方向（选择/装备/解除/锁定）。

### 英译中
- 短词先定词性与语境（如 `Save` 可为保存或救援，`Charge` 可为充能、冲锋或费用），禁止全局硬替。
- 核对代词指向、否定范围、情态强度（may/can/must）、比较关系与单位。
- 区分大小写敏感的资源键与显示文本（如 `US` 与 `us`）。
- 保留程序所需的复数/性别/条件分支与占位符，即使中文表面相同也不删分支；仅格式支持时调整命名参数顺序，不盲目重排 `%s` 等位置参数。
- 拼接字符串用真实参数组合检查单复数、空格、冠词与省略号。

### 共用语言工程检查
- 汉字、标点、拉丁字母、数字、重音符号与按钮图标均纳入字形覆盖；英文版未必具备中文字库或 CJK 断行逻辑。
- 容量约束分别看编码字节数、码元、字符数与像素宽度；英文变成更少汉字也可能占用更多字节。
- 检查行首/行尾禁则、拉丁词及型号断行、全半角标点、数字/单位间距与中英基线。

## 4. 术语与残留扫描

- **术语表字段**：原文语言、原文、采用译名、别名/禁用变体、类型、适用游戏/版本、依据、批准状态、出现位置、例外。复合词（公司简称、部门、队名）分别建项，采用最长匹配与词边界，替换后复查普通词与资源键是否误改。未经用户指定不自行裁定官方译名与旧民间译名孰优。
- **残留扫描**：假名、未译英文、原译相同、乱码、替代字符、空译文与术语变体均属候选信号，逐条判定为修复/正确保留/误报/待查。扫描最终回写后的资源，不只扫译文表；贴图残留单独盘点，字库图集里的假名不等于漏译界面。

## 5. 校对表设计与返表回填

### 导出校对表
- 若用户提供了指定样表，优先遵循用户样表（可选的任务汇总样表模板见 [review-workbook-template.md](review-workbook-template.md)）。
- 通用推荐列：编号、场景/说话人、原文语言、原文、当前中文、校对后中文、备注、状态；技术 ID 与原文指纹放附表或隐藏列。原文快照不可变；正文只放本轮需人工处理的条目，排除项保留映射与理由另存。
- 导出 CSV/XLSX 时防止以 `=` 开头的文本被解释为公式，同时保留回写所需原值。

### 收回返表与确定采用稿
- 保留返表原件、原始导出快照、稳定 ID/分段映射与构建指纹；实际回填从最新已确认构建与译文继承，不以旧生成器覆盖后来修复。
- 同时检查“修订中文”与允许编辑的“现用中文”列；常见约定是非空修订优先，修订为空但现用列相对快照确有变化时纳入；两列矛盾时保留冲突证据。
- 将 `None` 与空字符串在比较层视为同值，避免表格软件重存造成假修改；但不据此清空游戏文本，有意删除须有明确标记。禁止全局去空格、折叠换行或 NFKC 规范化后直接回填。
- 长文续行按导出时的分段契约重组后再比较完整条目；一逻辑句对应多物理槽时按原有映射逐一写回与读回，分别统计编辑单元格、逻辑条目与物理位置。

### 区分四类校对状态
“返表出现过 / 明确审校通过 / 实际改过 / 当前构建已采用”是四种不同证据：
- 修订栏为空通常表示沿用原译，不能单凭空白判为未校对，也不能直接标成明确验收通过；找不到历史返表只写“未找到记录”。
- 生成“仅待校对”表时合并历史返表覆盖；已返表但与现版译文不同的单列为“已返表但现译有差异”，避免重复劳动。

### 手误修订与简易 Word 记录
- 获准修明显错字时，仅修有上下文支持的同音错字、重复字、误标点或明确漏字；保留独特译名、文风与术语偏好。
- 维护手误清单：稳定 ID、原表位置、返稿原句（照录错字）、疑似问题、建议改法、实际采用稿与处理状态。超出明确错字授权的补全或润色列为待核对项。
- 导出中文 DOCX 预览若出现方框/缺字，先排查渲染环境（如 LibreOffice/Fontconfig）是否能找到对应中文字体族及文档样式是否残留主题字体，不要把文档渲染问题误判为游戏字库问题。
