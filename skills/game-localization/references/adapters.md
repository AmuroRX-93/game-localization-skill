# 跨游戏适配器约定

可复用的是工程闭环；读写器、补丁地址和数值约束属于具体游戏版本。本文是开发约定，仓库不宣称已实现下述平台适配器。

## 选择最少侵入路径

1. 有官方语言资源接口、源码或翻译模板：优先使用其 ID、导出／导入和字体／语言资源机制，避免不必要的二进制逆向。
2. 有成熟格式插件：核对工具版本及样本，先往返测试。可读不一定可写，某变体支持不代表同扩展名全支持。
3. 只有成品资源：定位容器、压缩、文本／字库／指针与加载引用；未知格式先研究最小样本，保留不确定项。
4. 只获屏幕／音频：可做临时理解辅助和问题采集；屏幕 OCR 翻译不能宣称等于完整可封回汉化。

源工程条件下，Ren'Py 可分别处理对白、界面、图片和样式，Unity 可借语言表及伪本地化做测试，Unreal 需同时处理语言数据和文化设置。这里是选择路径的例子，具体 API 以项目匹配版本文档为准，不能把编辑器功能假设为商业成品中也可用。来源见 [资料](sources.md)。

## 每个适配器留下这些信息

- 支持：平台、地区、实际版本、输入哈希集合、工具版本／提交；明确不支持变体。
- 发现：枚举外层及嵌套成员，输出稳定 ID、原始字节指纹、解析成功／未知状态。
- 抽取：源文、编码／字码、上下文、控制码、指针／长度约束、物理副本。
- 校验：编码可逆、引用有效、控制码语义、长度边界、重复 ID、内部键保护。
- 写回：干净基线＋经审校条目生成候选；更新父索引／长度／压缩；回读验证。
- 显示：字体消费者、图集 UV、纹理格式、内存和 UI 约束。
- 验收：可重复的场景入口、构建指纹、环境及证据。

与清单工具对接时，适配器输出 [ledger.md](ledger.md) 的 JSON。控制码必须由了解游戏格式的解析器提取；不能用一个全局正则解释所有游戏的 `%`、花括号或二进制标记。可重排的命名变量和必须保持顺序的无名变量分别处理；工具只比较适配器提供的受保护 token 列表。

## 支持声明

区分“识别”“可抽取”“可写回”“经过目标游戏验证”。新游戏先通过代表性小样再扩大；没有样本不要声称某引擎／主机全支持。共享抽象与专有逻辑分开，增加变体时不破坏旧样本。
