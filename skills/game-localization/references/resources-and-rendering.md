# 资源写回、字库和界面

## 封包与指针

记录端序、编码、长度单位、地址基准、对齐、压缩、校验、成员顺序和加载方式。原样往返先验证未修改成员逐字节一致；压缩表示不同则解释差异并比较解压成员。不能仅靠同一读写器互证；补充独立读回、边界断言和已知样本。

长度可能是字符、字节、含终止符长度或对齐块数；指针可能相对文件头、表基址或运行地址。传统 ROM 还可能有 bank／映射差异、DTE／MTE 压缩及嵌入指针。翻译增长必须计算新位置并修正全部引用，不能把后续字节整体往后推就结束。选择重定位／字宽调整／可验证的编码扩展前，先确认加载器边界。

顺序字符串池里多一个 NUL 能使后续条目全错位；保留空条目、控制码和结束标记。回填核对指针范围、条目数、成员长度、父容器长度及未修改区域。内部资源键、文件名、路径分隔符与大小写不能随文字翻译或随手规范化。

脚本中的空格、换行和注释邻接可能是词法分隔符。按游戏实际 tokenizer 验证条目分组和顺序，不能只数物理行。AC2 曾因标签与注释之间的空格丢失，使 256 个解析条目变为 255；修正这一缺陷不等于已证实它是玩家菜单故障的唯一原因。

控制码按引擎语法匹配：格式限定 ASCII 数字时用 `[0-9]` 而非 Unicode `\d`，明确控制码的终点，避免吞入紧邻的全角数字/中文。用“控制码＋全角数字”、连续控制码、空串等真实边界验证原字节保留。

## 字码、字形、排版分开

维护语义 Unicode → 游戏字码 → 字形索引 → 图集页／UV → 字宽／轴承／基线。旧汉化可能借用日文字位，一个旧字形位置可能被不同语义字符引用；换字体前发现并拆分这种冲突，不能按其中一个字符统一重画。

所需字符来自文本、动态变量、命名界面、数字、标点、拉丁字母和必要回退。抽取文本没出现，不代表不可达。普通、双倍、前端、战斗、广播字体可能有不同消费者；视觉风格统一不等于只需一个文件。

同一游戏的短按钮也可能走单字节渲染器，正文走双字节渲染器；正文正常不能证明按钮入口兼容中文。先追踪各入口如何读取字码，必要的程序补丁单独留白名单与原指令，验证原 ASCII 路径仍正常。逐消费者统计行宽、标点、变量最大展开长度、分页与图示/等待事件，不能把某作的“每行15字”设成全游戏通用值。

已烘焙到游戏纹理的字体与构建机字体分开：接收者无需为图集显示安装构建用 TTF/OTF；缺字先查字码映射、资源版本和加载层，不直接要求安装桌面字体。借用原日文字位时记录冲突与对玩家自定义名字的影响。

验证编码往返、每个需要字码的覆盖、非空字形和替代框；导出带语义标签的字形接触表，重映射字形逐个核对。能编码不等于引擎接受。整套换字体时，逐字映射检查不能被少数截图代替。

## UI 贴图

按原 UI 和用户选择制定正文／标题／字幕的字体层级，原尺寸预览后推广。统一字体指遵守层级和度量，不是所有地方同字号。记录来源与许可证。

每个文字区记录 sprite UV、缩放、对齐锚点、baseline、留白、裁切、选中／禁用状态。图集尺寸不等于实际可见范围。按视觉高度和基线对齐左右手、数值与单位、同组标题；文字放得下仍要检查读起来是否自然。

保留原纹理的像素排列、调色板、alpha 约定、mipmap、swizzle、透明边缘和压缩。不要假设 alpha 都是 0–255，或同透明度的颜色都可用来排字。修改框以外像素和边框不变；确需整体转换时记录验证依据。

擦除旧字前确认底图的横向/纵向渐变、网格、竖线、描边与选中高亮；逐行复制左边缘单色会抹掉横向渐变。优先从匹配原版和干净采样重建背景，只遮去文字及其阴影，不能用大块纯色覆盖装饰。压缩纹理以实际重编码块为修改边界，独立解码比较非目标块和恢复的细节。

大标题模糊先区分字形采样分辨率、图集分片/UV、引擎缩放、基线、颜色/alpha 与滤波。单纯放大或描粗可能加重颗粒、撞线或裁切；检查原尺寸和实际显示尺寸，并核对分片顺序及透明边缘。重排字不等于提高原始贴图分辨率，真实渲染前不宣传“高清”。

重复资源按内容、结构和引用确认身份。不同模式同名包可能子索引不同，每个物理副本写入后独立解码预览。AI 可辅助底图修复，但最终文字用可校验排字；若图像生成参与文字，逐字和非目标区域对比不可省。

## 内存

主机 RAM 不能代替被模拟主机的地址空间与游戏堆限制。记录文件大小、解压大小、纹理实际分配、对齐／头部开销、同时驻留量、加载释放时机、总空闲和最大连续块。

用实测高峰比较申请大小与最大连续块；单一现场不是全游戏最坏上界。减少资源优先无损去重、atlas 重排和经引用分析证明不可达的页，保留必要字码与 metrics。独立解码比较像素／度量，更新消费者和父容器长度。仅压缩磁盘文件未必减少 RAM。

扩大图集、提高清晰度和转格式先预算峰值；不要边批量换高清字库边等启动崩溃才测。申请失败返回值未检查和字库过大是两个层面的缺陷：缩小字库不等于已经加入失败保护。没有调用链和平台验证，不盲改内存地图、不承诺强扩模拟内存。

保存精确构建、申请长度、返回指针、载入资源、日志／现场与触发步骤，重测原场景及其他高驻留场景。
