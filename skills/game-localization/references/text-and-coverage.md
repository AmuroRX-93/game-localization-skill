# 文本、术语与覆盖率

## 建立分母

资源总表包含外层文件与指纹、容器链、成员标识／偏移、类别、解析状态、加载证据、关联条目、处理决定。查找文本表、脚本／可执行文件字符串、按键帮助、功能贴图、片头标题、字幕，以及更新、DLC、安装副本和单人／多人变体。每类记为找到、经证据排除或待查，未知容器不能算无文本。

区分物理出现次数、唯一文本 ID、唯一字符串、段落和表格行数。360 段邮件与 5,361 个跨类别条目不是同一分母；列出每个工作表条数及汇总方式。改变不等于翻译，未改变也可能是正确保留的型号。可见条目分别标记翻译、保留、排除、待定；后两种完成决定需要理由。覆盖率仅针对明确版本和已盘点集合。

## 原文与中文对齐

- 同版本按稳定 ID 和上下文对齐；跨平台有对应表，标出一对多、拆分／合并、版本独有内容。不要只按行号匹配。
- 自定义字码先建立“游戏字码→实际字形→语义字符”。不能把旧 Shift-JIS 解码结果直接当中文原文。
- 原文快照不可变。回收校对表以 ID 和原文指纹定位，拒绝重复 ID、未知 ID、基线变化及冲突修订。
- 内部路径、资源键与显示文字分开；同词面在参数、对话、人名中可能不同义。

## 校对表与审校

推荐列：编号、场景／说话人、日文原文、当前中文、校对后中文、备注、状态。技术身份和原文指纹放附表或隐藏列，导出不丢。少量真实正文先确认格式，再做全量。保留换行、并排对照、修订栏可编辑；实际保存并重新打开确认可用。

团队表格字体与游戏字库不是同一要求；例如含英文整格用某字体是特定团队偏好，不是通用标准。导出 CSV 时防止游戏文本被表格软件解释为公式，同时保持回写所需原值。

逐条审校留有结果或未审标记。结合相邻片段核对否定、条件、单位、按键动作、说话人及分支；拼接提示用真实参数读整句。翻译记忆复用时，源文或上下文变更使旧审校失效，不能静默保留“已通过”。

## 术语规则

术语表列：原文、采用译名、别名／禁用变体、类型、适用游戏／版本、依据、批准状态、出现位置、例外。按用户指定来源优先级统一，未经指定不自行决定官方地区译名与旧民间译名孰优。

公司简称、部门、队名等复合词分别建项；使用最长匹配和边界，替换后检查普通词与资源键是否误改。另一作的术语可作为参考，但“固定目标”和“重置目标”等不同机制不能强行统一。

## 残留扫描

假名、未翻译英文、原译完全相同、乱码、替代字符、空译文、术语变体都是候选信号，每条需判为修复／正确保留／误报／待查。扫描最终回写后的资源，不只扫描译文表。

贴图残留单独盘点；OCR 对小字、透明通道和装饰字会漏，不能只靠 OCR。字体图集里的假名不等于漏译界面。声称无残留时说明规则、范围和未解析数量。
