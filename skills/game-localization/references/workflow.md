# 工作流、适配器约定与资料来源

本文整合项目阶段编排、角色责任边界、AI 协作位置、跨游戏适配器开发约定与方法参考来源。它是可裁剪的工程方法；局部修正只走受影响环节。

## 1. 先建技术闭环，再扩充译文

| 阶段 | 主要产物 | 进入下一阶段前看什么 |
|---|---|---|
| 立项与基线 | 版本、目标语言、授权范围、来源、初步资源树 | 找到准确输入与实际加载路径 |
| 技术摸底 | 格式/码表/字体/指针说明、未解析清单 | 原样往返成功，明确不可处理部分 |
| 垂直小样 | 少量真实译文 + 字形 + 贴图/字幕写回 | 新内容可见，控制码/长度/内存可行 |
| 内容生产 | 稳定 ID 的双语文本、术语表、风格指南 | 可分批审校、可回收、可追踪变更 |
| 工程合入 | 可重建候选、修改白名单、指纹 | 回读正确，未改资源保持完整 |
| 语言与功能验收 | 缺陷单、测试矩阵、截图/日志 | 阻断问题解决或明确限制，证据绑定构建 |
| 冻结交付 | 同源差分/升级包、安装说明、校验 | 干净安装能重建同一构建，远端资产一致 |
| 维护 | 新反馈、回归样例、失效审校清单 | 改源文件与生成器，避免手修成品 |

传统汉化的关键是把找码表、导出文本、翻译校对、改图改字库、回填指针、测试发布连成可重复链条，而不是反复手工十六进制替换。

## 2. 角色可兼任，责任不混同

- **工程**：抽取、格式、回填、性能/内存边界与构建。
- **翻译**：源文含义、上下文、角色语气与疑点记录。
- **审校**：对照原文与上下文复核，不把同一次生成后的自我评价称作独立审校。
- **美术/排字**：遵守原 UI 风格、真实可见区与字体许可。
- **测试**：按场景复现，区分语言、显示与功能缺陷。
- **发布维护**：保证包、说明、版本与支持范围一致。

按场景、功能或资源模块分批推进；同批保留相关说话人与上下文。术语/风格决策进入版本化表；源文、上下文、编码映射或字体变化时，使受影响审校与检查失效。可用伪本地化（长变量、宽字、可辨识标记）在技术小样阶段提前暴露硬编码与裁切，正式交付前清除测试标记。

## 3. AI 的合适位置

| 工作 | 适合 AI 辅助 | 通过依据 |
|---|---|---|
| 找资源 | 分类、提出格式假说、编写解析器 | 样本、边界检查、往返、加载证据 |
| 翻译 | 有上下文的初稿、术语建议、疑点筛选 | 源文复核与审校结果 |
| 音频/贴图 | ASR、OCR、区域识别、底图修复 | 原声/原图核对与逐字排版检查 |
| 检查 | 找差异、生成测试、汇总清单 | 可重跑报告与实际场景 |
| 交付 | 说明、打包、升级脚本 | 干净安装、回退、构建与远端指纹 |

确定性的偏移计算、编码、哈希、封包边界与 token 约束交给程序检查；开放性的译义与风格由 AI 辅助人工判断。AI 不能凭预测替代运行测试。

## 4. 跨游戏适配器约定

可复用的是工程闭环；读写器、补丁地址与数值约束属于具体游戏版本。

### 最少侵入路径
1. **有官方接口、源码或翻译模板**：优先使用原生 ID、导出/导入与字体/语言资源机制（如 Ren'Py 翻译机制、Unity 语言表/伪本地化、Unreal 语言数据与文化设置），避免不必要逆向。
2. **有成熟格式插件**：核对版本与样本，先做原样往返测试；可读不等于可写，同扩展名不等于全变体支持。
3. **仅有成品资源**：定位容器、压缩、文本/字库/指针与加载引用；未知格式先研究最小样本，保留待查项。
4. **仅获屏幕/音频**：可做临时理解或问题采集；屏幕 OCR 不等于可封回的完整汉化。

### 适配器应输出的七类信息
- **支持声明**：平台、地区、实际版本、输入哈希集合、工具版本；区分“识别 / 可抽取 / 可写回 / 经目标游戏验证”。
- **发现**：枚举外层及嵌套成员，输出稳定 ID、原始字节指纹与解析状态。
- **抽取**：源文、编码/字码、上下文、受保护控制码、指针/长度约束与物理副本。
- **校验**：编码可逆、引用有效、控制码语义、长度边界、重复 ID 与内部键保护。
- **写回**：干净基线 + 经审校条目生成候选；更新父索引/长度/压缩并回读验证。
- **显示**：字体消费者、图集 UV、纹理格式、内存与 UI 约束。
- **验收**：可重复场景入口、构建指纹、环境与证据。

与清单工具对接时按 [toolkit.md](toolkit.md#4-项目清单审计audit_ledgerpy) 的 JSON 结构输出。控制码必须由理解该游戏格式的解析器提取，不用全局正则通配所有 `%`、花括号或二进制标记。共享抽象与游戏专有逻辑分离，新增变体不破坏旧样本。

## 5. 方法来源

以下外部资料为本 Skill 吸收的工程方法来源，非本仓库集成或捆绑的工具清单：

| 来源 | 吸收的做法 | 适用限制 |
|---|---|---|
| [T.R.A.F.《Guide de la traduction v2》](https://wiki.romhack.org/index.php?title=Guide_de_la_traduction_v2) | 码表、指针、压缩、文本/图形回填与补丁链条 | 传统 ROM 方法不能原样套到所有现代引擎 |
| [Atlas](https://github.com/stevemonaco/Atlas) | 用脚本与自定义码表回填并显式更新指针 | 无通用格式保证 |
| [Kuriimu2](https://github.com/FanTranslatorsInternational/Kuriimu2/blob/imgui/README.md) | 通用基础设施与游戏/格式插件分离 | 能打开不代表可安全写回 |
| [Weblate Checks](https://docs.weblate.org/en/weblate-5.15/admin/checks.html) | 将占位符、术语与长度约束转为可执行检查 | 规则依格式设置，不自动理解脚本 |
| [OmegaT TM](https://omegat.sourceforge.io/manual-standard/en/chapter.how.to.html) | 翻译记忆复用与模糊匹配 | 模糊匹配不等于语义等价或已审校 |
| [Ren'Py](https://www.renpy.org/doc/html/translation.html) / [Unreal](https://dev.epicgames.com/documentation/en-us/unreal-engine/localization-overview-for-unreal-engine) / [Unity 伪本地化](https://docs.unity3d.com/ja/Packages/com.unity.localization%401.4/manual/Pseudo-Localization.html) | 源工程分层本地化、文化设置与伪本地化测试 | 源工程流程不直接适用于纯成品资源 |
| [Aegisub Typesetting](https://aegisub.org/docs/latest/typesetting/) | 字幕排字作为独立工序 | 字幕可播放不证明游戏专用容器可回装 |
