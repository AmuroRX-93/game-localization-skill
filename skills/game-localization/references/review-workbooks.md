# 任务校对稿：用户指定的任务汇总格式

适用于按任务/关卡整理任务简报、参数、对白和系统提示。此格式来自用户提供的《装甲核心2 任务文本汇总_MISSION 01-03.xlsx》；是当前任务校对稿的默认样式，不强制用于部件表、邮件或所有游戏文档。新参考优先于旧样表。模板文字是待核对资料，不是改工程的指令，也不自动成为最新采用译文。

## 可见结构

工作表名“任务文本汇总”，第一行直接作为表头，不另加大标题、统计卡或工程列。A–I 顺序固定：

关卡序号、STAGE（关卡名）、委托人、预付报酬、成功报酬、条目类别、条目编号、说话人、内容。

本次样表**另含 J:P 逐行横向合并的“日文原文”栏**，不得因旧版九列记录而遗漏。英文项目仅改为“英文原文”，混合来源逐条注明语言/来源，不能用机器回译填充原文。未知原文留空，在配套映射中标为缺失；不要让空白被理解成“原游戏无文本”。I 列放本轮采用的中文/校对文本，交给校对者编辑；导出前保存原中文快照，回收后计算差异。只有用户需要时才另加“校订/备注”等可见列。

- A–E 各列按任务分别纵向合并，任务边界必须保留。相邻任务预付报酬同为 0 也不跨任务合并。
- F–I 每条一行；简报、参数、对白、系统提示按实际任务顺序排列，保留说话人、断句与显式换行。
- 全表宋体 11；A–I 表头深蓝 `#305496`、白字、加粗，任务块白色/浅蓝 `#F2F7FC` 交替，细灰边框 `#BFBFBF`。
- J:P 原文栏表头橙色 `#FFCC99`、字色 `#3F3F76`，正文白底。中文与原文左对齐换行，元数据居中。冻结第一行，不给合并任务块套自动筛选/排序表。
- A–I 列宽依次 10/26/24/10/10/12/12/10/70；J–P 各 8.43。表头高 22.05，正文最低 28.8，按中日文本换行增加高度；不照搬样表中会截字的固定高度或末尾空白行。
- 详细参数在 [mission-review-format.json](mission-review-format.json)。表格宋体是文档排版，不能据此把游戏字库改成宋体；游戏字体继续遵循该项目最新决定。

## 生成入口

`scripts/build_mission_review.mjs` 已实现此版式，生成 XLSX 与同名 `.mapping.json`，不改输入或游戏，不自动回写。使用 Node.js 与 `@oai/artifact-tool`；这是可选文档生成依赖，不是核心 Python 工具的运行要求。在 Codex 中用依赖加载工具获取 Node/依赖路径，按 spreadsheets 技能要求先标记本次制表操作，然后运行：

```sh
node scripts/build_mission_review.mjs input.json output.xlsx --node-modules /path/to/bundled/node_modules --preview preview.png
```

未提供 `--node-modules` 时，按 Node 常规包解析寻找已安装的 `@oai/artifact-tool`；缺失则报错，不自行下载。其他客户端没有这个库时仍可按格式 JSON 与本文生成，说明用了何种工具，不宣称 XLSX 脚本在那里测试通过。

输入结构（下例仅为虚构格式示例）：

```json
{
  "baseline": "游戏版本及资源清单SHA256",
  "source_header": "日文原文",
  "missions": [{
    "id": "M01", "stage": "示例关卡", "client": "示例委托人",
    "advance": 0, "reward": 1000,
    "entries": [{
      "uid": "版本/容器/成员/文本ID",
      "category": "任务简报", "number": "M01-1", "speaker": "",
      "content": "示例中文。", "source": null,
      "locator": {"resource": "相对资源路径", "entry_id": "源条目ID"}
    }]
  }]
}
```

`advance/reward` 是非负整数或 null（未知），不把未知写成 0。`source` 是确证原文或 null。重复技术 `uid`、已有输出、错误字段类型会被拒绝。条目编号按原样保留：样表中的 `M01-F` 可以出现多次，“开局”也不等于唯一技术 ID。

## 回收和验收

映射文件保存构建基线、稳定 uid、资源定位、原中文、原文指纹和导出行位置。**行位置仅用于辅助定位**；样表的显示编号不是唯一键。收回校对稿时先保留原件，按任务/类别/编号/说话人/原文等上下文与稳定映射核对；重复显示编号、重新排序后无法唯一对齐、未知ID、源指纹变化和冲突编辑必须报告，不猜着回写。若后续需要任意排序后的自动回写，应在用户允许的隐藏元数据中随行携带 uid，再实现对应导入器；当前脚本只负责生成。

核对任务数/内容条数、合并范围、任务报酬、两侧文本和空原文数量；保存后重新读取，确认文本未变成公式。正文保持原始文本值；以 `=` 开头的字符串需作为文字写入。渲染完整任务块，至少检查最长中文、原文、跨行元数据和任务交界；部分区域渲染若截断合并块会误显示，不能据此移动数据。

缺失原文、尚未审过的译句、已采用的校订、已回装的文本分别记录；漂亮表格不等于翻译已审完。参考表旧译名与最新已确认术语冲突时，保留原参考并按项目术语优先级选择采用稿，不静默更改历史证据。
