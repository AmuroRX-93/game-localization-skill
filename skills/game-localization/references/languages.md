# 日文与英文游戏汉化

共同目标是从实际加载的日文或英文资源生成中文。先确定主译版本、源语言、目标地区（如简体中文或繁体中文）和参考译本。不要为了套用历史案例强制寻找日文版，或通过第三种语言中转已有原文。

## 源文与版本

- 日文、英文可能来自不同发行版、剧情修订或审核版本。以主译版本的 ID、场景和分支为准；另一版只作注明出处的参考。
- 混合资源按条目标注语言；型号、品牌、按键和内部键单独分类，不以拉丁字母或假名存在就断言漏译。
- 双版本无法可靠对应的行留空并标注缺失／待核对，不把 AI 生成的日文或英文写成“原文”。译文回写绑定主译资源及原文指纹。

## 日译中

- 根据前后句、说话人、事件和分支补足省略的主语／宾语。证据不足的身份与因果先标待核对，不擅自补剧情。
- 区别人名、公司、队伍、武器名和普通片假名借词；按批准术语表处理长音、简称与复合词，避免只替换词根。
- 敬语、口癖、称呼与人物关系保持一致；片假名英文词应核对游戏内设定，不能仅靠音译反推唯一英文原名。
- 检查同形汉字、否定、条件与动作方向；如选择、装备、解除、锁定等要匹配游戏实际操作。

## 英译中

- 短词先确定词性与场景。例如 `Save` 可以是保存操作或救援动作，`Charge` 可以是充能、冲锋或费用；同一个词不能一律全局替换。
- 核对代词指向、否定范围、情态强度、比较关系与单位；不要擅自把 may/can/must 等提示都译成强制要求。
- 人名、缩写、品牌、型号与普通词分类。大小写不是唯一依据；确认 `US` 与 `us`、显示名称与大小写敏感资源键不会互相污染。
- 保留程序所需的复数／性别／条件分支和占位符，即使中文表面相同也不能删除分支。仅当格式支持时调整带名参数顺序，不盲目重排 `%s` 等位置参数。
- 拼接字符串需用真实参数组合检查，例如单复数、数字前后空格、冠词及省略号；不能只逐段翻译后假定整句成立。

## 两种语言共用的工程检查

- 汉字、标点、拉丁字母、数字、重音符号与按钮图标都纳入字形覆盖；英文版未必具备中文字库或中日韩断行逻辑。
- 容量约束分别记录编码字节数、码元、字符数与像素宽度。英文变成较少的汉字也可能占更多存储字节；不按字符数推断缓冲区安全。
- 检查中文行首／行尾禁则、拉丁词及型号断行、半角与全角标点、数字／单位间距。字号、行高和中英基线在实际 UI 中验证。
- 残留扫描同时使用源文未变、词汇候选、字符类别与允许保留表。英文常见词命中、假名命中都只是线索；展示文本、资源键和商标不能混算。
- 语言质量、资源覆盖率和回填正确性分别验收；保留双方源文有助于校对，但不能证明任何一版资源已完整收录。

## 代表性审校样例

| 原文／情境 | 审校关注点 |
|---|---|
| `Charge` 出现在充能按钮与冲锋技能 | 分成不同语境条目，分别确定译名 |
| `Do not reload until the indicator turns green.` | 否定和时间条件不能丢失 |
| `You have {count} item(s).` 或格式化复数分支 | 数字变量及实际分支结构完整保留 |
| `彼にはまだ伝えていない。`，无人物上下文 | 不编造“他”是谁，保留待核对上下文 |
| 日文主译版本存在一段，英文版没有 | 标为版本差异，不生成伪英文原文 |

这些是方法样例，并非已在某个游戏中验证过的译文。
