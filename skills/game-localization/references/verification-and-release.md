# 验证、排障与发布交付

涵盖按证据定位缺陷、五层证据模型、运行测试矩阵、构建/差分/便携环境验证以及发布与缺陷回收。

## 1. 按证据定位故障

- 记录症状、准确页面/关卡、输入动作、构建指纹、环境版本、最新日志与截图，区分：译义错误、映射错误、排版裁切、错资源、漏加载、内存/封包故障、模拟器兼容。
- 同配置对照原版与候选，再逐一隔离字体、文本、贴图、影片、更新/DLC；原版也崩不直接怪汉化，错误日志是线索而非因果证明。
- 路径核查涵盖实际启动入口、大小写、分隔符与虚拟文件系统；宿主可见不代表游戏按请求路径读到。
- 局部花屏与单关卡异常分别建复现点；回退某项试验时仅撤销该变更，保留已采用的译文与 UI 修复，不拿旧整包覆盖新状态。

## 2. 五层证据模型

| 层次 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 清单与解析 | 已解析范围、待查资源、稳定 ID | 没有任何遗漏 |
| 语言与显示静态检查 | 控制码、术语、字形、UV/排版候选 | 游戏实际读取该资源 |
| 写回与往返 | 指针/容器可重建、修改范围受控 | 程序不崩、内存足够 |
| 运行验证 | 指定构建在指定平台的指定场景通过 | 全版本、全平台、全关卡通过 |
| 安装与发布验证 | 接收者能重建目标、远端资产一致 | 所有剧情译义准确 |

每条测试绑定构建哈希；构建变更后按依赖使相关测试失效，不拿旧测试替新构建背书。分别标注源码分析、自动检查、用户反馈与直接观察。

## 3. 运行测试矩阵

- 按改动影响挑选场景：冷启动、读取复制的游戏内存档、主菜单/设置/按键帮助、最长文字与动态变量、改名、商店/装备、剧情分支、战斗、结算、存读档、返回菜单、退出重进。
- 字体/内存改动覆盖高驻留场景及反复进出；字幕覆盖首次/重播、跳过与转场；更新/DLC 测到进入内容、结算与存读档。
- 验证新二进制须**冷启动并读取游戏内存档**，旧即时存档可能携带旧程序和旧字库。使用测试存档副本；独立隔离配置需保留完成测试所需的输入设备/手柄映射。
- 测试矩阵未执行项如实标“未测”，工具无法操作窗口时交付复现路径请用户实测，不虚报观察结果。

## 4. 构建、安装器与便携环境验证

- **干净基线重建**：发布包从清单与输入哈希可核对的干净基线构建，不直接打包正在游玩的实验目录；构建后复跑预检确认收敛。
- **差分与安装器安全**：
  - 区分原版首次安装与旧汉化升级，用精确哈希匹配基线，拒绝未知/混合版本。
  - 预检输入、目标版本、磁盘空间与写权限；写临时输出、校验通过后再提交，失败清理半成品。原地多文件覆盖需可验证备份与回退。
  - 等待玩家退出后安装时，以可执行路径和进程身份判定进程，重新核对基线与存档快照；资源写入后不立即声称仍在运行的旧进程已生效。
  - 负例测试覆盖：错误基线、缺分卷、已有目标、中文/空格路径、只读权限、空间不足、意外中断、重复安装与还原；大文件流式处理。
- **随包便携运行时（如内置 Python）**：
  - 验证移动目录、不同工作目录及外部 `PYTHONHOME`/`PYTHONPATH` 污染隔离；用 `Path(__file__).resolve().parent` 定位本地模块，不依赖系统 Python 或联网安装。
  - 分别记录原始上游包哈希与展开/裁剪后的最终目录哈希及许可证；按架构（Windows x64/ARM64、macOS Apple Silicon/Intel、Linux x64/ARM64）分开标注“已运行验证”与“仅静态检查”。
- **Windows 安装器排错**：批处理末尾的 `Press any key to continue` 仅是暂停，先查它之前的首个报错与日志，区分运行时缺失、目录多套一层、路径不匹配与编码异常。遇到 GBK/UTF-8 异常定位具体读取边界，子进程保留原始字节再按已知编码解码，不靠全局 `errors="ignore"` 掩盖问题。

## 5. 发布与缺陷回收

- **面向玩家的包结构**：入口清晰（当前版本、先读说明、对应平台入口、支持基线、校验、旧版升级与回退方式），说明随包提供不依赖聊天记录；不夹带个人存档、BIOS、密钥、账号或未审查工具。
- **上传复核**：干净目录按包内说明完成一次安装并核对输出指纹；远端上传后重新读取 release 状态、资产名、大小与哈希，避免请求报错后重复追加资产。
- **缺陷单与闭环**：收到新问题时记录原文 ID/页面、复现步骤、预期/实际、构建哈希与证据；修复落回源译文/源资产/生成器并重新构建，不手修成品包，同时补充对应回归检查。
