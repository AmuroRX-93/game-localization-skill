# 历史案例与推广边界

以下为去敏后的跨游戏工程教训，不含私人路径、对话原文、存档或游戏资产。历史记录中的候选与未验证项不视为已完成成果。

| 案例现象 | 工程教训 | 不能推广成什么 |
|---|---|---|
| 译文已写入，但另一层安装资源仍为原版（如 ACFA） | 先查清本体、安装数据与更新的加载优先级 | 所有游戏都要盲删或覆盖全部缓存 |
| 同系列相邻作品格式/编码不同（如 AC4 与 ACFA） | 术语可参考，二进制结构必须逐版本验证 | 同系列补丁可直接互用 |
| 换字体后出现异字混用（如“框/夷”“臂/崖”） | 重建 `语义 → 字码 → 字形` 映射并查共享字位冲突 | 把显示错字直接改译文 |
| 高清字体与界面改动后出现启动/显示回归 | 小步隔离验证包结构、层级标记与内存预算 | 高清一定不可行，或缩字一定修好 |
| 启动资源路径分隔符被误改 | 内部路径不是可译文本 | 所有路径都应统一成某种斜杠 |
| 文件存在但游戏报找不到音频 | 排查游戏实际请求路径与虚拟文件系统大小写行为 | 一律把全部文件名改小写 |
| 字幕文件有内容但重播随机漏句 | 分开验证文本、触发事件窗与播放时序 | 有字幕数据就等于字幕汉化完成 |
| 重封装过场片桌面可播放，游戏内播完黑屏 | 必须测全片、跳过、加载与进入后续场景 | 单条解码日志足以确定封装根因 |
| PS2 移植中文字库触发分配失败后零地址写崩 | 预算最大连续块，资源压缩与错误处理分开验收 | 宿主内存大就没有模拟内存风险 |
| 顺序帮助文本池多/少终止符导致错位或空白 | 核查终止符、条目次序与真实字体消费者 | 空白都靠重新翻译修复 |
| 相似 HUD 资源在不同子索引 | 用结构、指纹与回读预览确认每个物理副本 | 同名父包使用相同子索引 |
| 标题字库灌入多余扩字导致进战斗黑屏 | 共用字体源与码表，按消费者保留扩字并复用合格字形 | 文件缩小比例等于显存节省比例，或所有游戏支持 LA8 |
| 校对者看到一页数百行，汇总报告却说数千条 | 工作表、段落、唯一条目与物理出现次数分开统计 | 数值越大越完整 |
| 多轮完整镜像堆积导致成品入口混乱 | 控制实验副本，保留干净基线与可重建脚本 | 不经检查删除所有旧资源 |

另注：传承或移植既有民间译文时，分别核实原作者、源帖日期与转载日期，写清“原汉化 / 移植 / 新增工作”；致谢不自动等同于获得再分发许可。
