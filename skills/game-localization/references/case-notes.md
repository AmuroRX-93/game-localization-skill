# 案例与边界

以下为经整理的工程经验，不包含私人对话原文、文件路径、存档或游戏资产。历史记录中的候选、失败和未验证项不应误作已经完成的成果。

| 案例 | 教训 | 不能推广成什么 |
|---|---|---|
| ACFA 译文存在，但另一层安装资源仍为原版 | 查清本体、安装数据和更新的加载优先级 | 所有游戏都要覆盖所有缓存 |
| AC4 与 ACFA 格式／编码不同 | 术语可参考，二进制格式逐版本验证 | 同系列补丁可直接互用 |
| AC4 换字体后“框／夷”“臂／崖”混用 | 重建语义→字码→字形映射，检测共享字位冲突 | 把显示错误直接改成另一段译文 |
| AC4 高清字体与界面改动出现启动／显示回归 | 小步验证；包结构、层级标记和资源预算分别查 | 高清一定不可行，或缩字一定修好 |
| ACV 启动资源路径分隔符曾被改错 | 内部路径不是可译文本 | 任意路径都应统一成某种斜杠 |
| 高达 UC 文件存在仍报找不到音频 | 看游戏实际请求路径与虚拟文件系统行为 | 一律把所有文件改小写 |
| 高达 UC 字幕文件有文字而重播仍随机漏句 | 文本、事件窗口和时序分别验证 | 有字幕数据就算完成字幕汉化 |
| 水天之泪重封装片可桌面解码，游戏过场后黑屏 | 测全片、跳过、加载和进入战斗 | 单条解码等待日志足以确定根因 |
| ACFF PS2 移植 PSP 中文字库触发分配失败后的零地址写入 | 预算连续内存，压缩资源与错误处理分开验收 | 主机内存大就没有模拟内存风险 |
| ACFF 顺序帮助文本池及字体绑定异常 | 检查终止符、条目次序和真实字体消费者 | 空白都靠重新翻译修复 |
| ACFF 相似 HUD 资源在不同子索引 | 用结构、指纹和回读预览识别副本 | 同名父包使用同一子索引 |
| ACFF 字形图像无损合并释放余量 | 保留字码与 metrics，验证每个字形和父包长度 | 删除没在正文出现的字码就安全 |
| 校对者看到一页数百行，报告说数千条 | 工作表、段落、物理出现次数分开统计 | 数值较大就代表更完整 |
| 多轮完整镜像累积、成品入口难找 | 控制副本、保留可重建资料，当前交付独立清楚 | 不经检查删除所有旧资源 |

ACFF 的一个候选优化在既有卡死现场估算中增加约 384 KiB 余量，保留全部字码并验证字形一致；这不等于有全地图峰值保证，也不等于已加入内存分配失败保护。这里刻意保留证据边界。

“游戏助手 1”的主要经验涵盖多作 PS3 汉化、加载层、影音、补丁交付；“游戏助手 2”补充启动故障、字形映射与 UI 风格返工；“游戏助手 3”主要涉及素材盘点、原作者溯源和局部排字，不是另一个完整汉化项目；“游戏助手 4”提供跨 PSP／PS2 移植、全量校对、内存、帮助页与升级发布经验。与汉化无关的日常设置和私人内容没有纳入 Skill。

原作者身份、源帖日期和转载日期需分别核实；不能照抄聊天中的错误年数。传统译文的传承应记清“原汉化／移植／新增工作”，致谢并不自动等于获得重新分发许可。
